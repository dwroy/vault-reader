# App description

Positioning and store-ready copy. Every claim below matches the current M1b build plus the Reading extension; do not advertise M2/M3 features, Android or write-back before they ship. Store keywords avoid third-party trademarks (App Review Guideline 2.3.7); the descriptions name Claude Code, Codex, Obsidian, GitHub and GitLab only to state compatibility.

## Positioning

Knowledge bases are increasingly written by AI agents. People hand material, ideas and tasks to Claude Code or Codex; the agents write Markdown, generate HTML pages, reorganize folders and add links inside a Git repository. Vault Reader is the other half: a native, read-only place to read that repository comfortably on a phone.

- **Plain text first.** The knowledge base is an ordinary GitHub or GitLab repository of Markdown, HTML, PDF and images. No proprietary format, no database, no lock-in.
- **Agent-friendly.** Agents maintain the vault the way they work best, through files and commits. The app never writes back, so it never conflicts with them.
- **Built for reading.** Directory, Reading shelf, search, heading outline, paper themes and automatic position recovery.

### Description

Agents organize. You read anywhere.

More and more knowledge bases are written by AI agents. You hand material, ideas and tasks to Claude Code or Codex; they write Markdown, generate HTML pages, reorganize folders and fill in links inside a Git repository. Vault Reader does the other half: it lets you read all of it comfortably on your phone.

Plain text first
· Your knowledge base is just a GitHub or GitLab repository: Markdown, HTML, PDF and images. No proprietary format, no database.
· Markdown with Obsidian wikilinks and embeds, highlights, footnotes, task lists and frontmatter tags. Existing Obsidian vaults read as-is.
· Standalone HTML pages open untouched in an isolated reader, ideal for agent-generated reports, handouts and visualizations.

Agent-friendly
· Agents maintain the vault the way they work best: files and commits. The app is strictly read-only and never writes back, so it never conflicts with them.
· Recent lists changed files by commit, so you can see what an agent just wrote.
· Books and articles in folders such as books, papers or articles, or in a reading list declared by the README, appear on the Reading shelf automatically.

Built for reading
· Directory-first browsing, quick switching between vaults, filename and full-text search.
· Heading outline, adjustable font size and four paper themes: system, light, sepia and dark.
· Reading position is remembered and survives font changes and content updates; Continue reading takes you straight back.
· Cached content stays readable offline.

Security and privacy
· Needs only a repository-scoped read-only token (GitHub Contents: Read-only, GitLab read_api), stored in the device Keychain and never exposed to web content.
· No server, no account. Reading history and preferences stay on the device.
